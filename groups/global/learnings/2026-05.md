## 2026-05-11 - Meeting: FitBot quality review + conference follow-ups

- **Ghostwriter model pattern**: Using one LLM to write messages in the style/persona of another (e.g. Claude ghostwriting for a fitness coach persona) can significantly improve naturalness without exposing the underlying model. Worth exploring in any user-facing conversational agent.
- **Bot-likeness invites boundary-testing**: Users who perceive they're talking to a bot are more likely to troll or test limits. Reducing explicit AI signals (robotic phrasing, emoji overuse, "bot" vibes in greetings) is a UX lever that also reduces adversarial behavior — not just a polish concern.
- **Premature planning erodes trust**: Jumping to a workout plan (or any structured output) before collecting sufficient context (nutrition, schedule, allergies) feels generic and breaks the illusion of a knowledgeable advisor. The agent should ask more before giving less.
- **Unit tests ≠ real conversation quality**: Thorough unit tests on individual skills don't catch the end-to-end conversation flow breaking. Manual spot-checks are insufficient at scale. E2E conversation simulation (even a handful of scripted scenarios) is essential before releasing to users.
- **Prompt bloating is a warning sign**: When you're adding more and more to a single system prompt to fix behavior, it's a signal to split into sub-agents or skills — not to keep patching. Architectural separation often outperforms prompt engineering at the margin.
- **Sub-agent architecture knowledge is a force multiplier**: Talking to practitioners who've built real production chat agents (not just reading blog posts) can shortcut months of trial-and-error on architecture decisions (memory, tool routing, context management).
